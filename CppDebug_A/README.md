# VANGUARD 算法组招新考核 —— 表达式计算器 Debug 任务

## 任务目标

在约 40 分钟内定位并修复表达式计算器 `expr.cpp` 中的问题，使程序能够正确处理表达式。

考查重点是复现问题、阅读已有代码、缩小范围、验证修复。

正式 Debug 版本将在当前代码中预先设置`⚠️四处⚠️`问题，你需要准确定位并修复。不会因为某处 Bug 无法修复而导致其他 Bug 无法排查，若无头绪可继续尝试修复其他 Bug 。

## 考查范围

- 允许修改：`expr.cpp`
- 只读参考：`expr.hpp`、`main.cpp`、`gen-expr.c`、`Makefile`
- 注意事项：除 `expr.cpp` 外，其他文件均不作为考察范围。允许为方便调试而修改其他文件，但对其他文件的修改不可作为考核评分依据，提交时注意恢复原样。若因修改导致 CI 测试无法通过，概不负责。

故障均为可通过测试发现的逻辑问题，例如运算符处理、递归求值、边界条件或状态管理。题目不设置编译失败或故意直接打印错误信息的故障；正常运行程序并输入测试用例，程序应表现为计算结果不正确、部分测试未通过、死循环或崩溃。

本示例用于熟悉考试框架，请先阅读代码并自行运行测试。正式 Debug 考核允许联网查阅资料，但禁止使用任何 AI 工具、代码补全工具或代写服务。不要修改测试文件中的期望答案来掩盖错误；修复和调试时记录复现命令、错误现象、定位过程及验证结果。

## 正确性判定

使用表达式生成器生成一批合法表达式测试用例，输入测试用例到表达式计算器，提示 `All tests passed!` 则测试成功。

## 目录结构

- `expr.cpp`：正则分词、括号检查、递归求值和错误处理。 ⚠️只考这个文件。其他不考，简单了解即可⚠️
- `expr.hpp`：计算器对外接口声明。
- `main.cpp`：交互模式与测试文件模式。
- `gen-expr.c`：生成随机表达式和参考结果。
- `Makefile`：构建规则和常用命令。
- `test`：示例测试文件，格式为“期望结果 表达式”。

## 构建与使用

```bash
make                                         # 构建计算器与表达式生成器
./build/expression_generator 100             # 生成 100 条测试数据
./build/expression_generator 100 > test      # 生成 100 条测试数据并保存到文件"test"
./build/expression_calculator                # 启动表达式计算器并手动输入表达式
./build/expression_calculator test           # 启动表达式计算器并将文件"test"的内容输入并批量测试
make clean                                   # 清除构建
```

批量测试模式只显示最终汇总。每条测试全部通过时提示 `All tests passed!`；若有测试失败，则逐条显示 `FAIL`、表达式、预期值和实际值。

## 基本要求

支持十进制数字、空格、`+`、`-`、`*`、`/` 和括号，接受复合计算过程中的负数结果，但不支持直接输入负数。

表达式内部每个复合运算结果均是 32 位有符号整数范围，测试用例应保证每个子表达式均不会溢出。负数结果必须正常输出；除零和非法表达式应保持现有错误处理行为。

如 `5 / 2 + 5 / 2`

按整数计算应该是 `5 / 2 + 5 / 2 = 2 + 2 = 4`

因此正确的最终结果为 `4` 而不是 `5`

修复后运行测试文件，也可自行设计若干覆盖优先级、括号、连续同级运算和边界值的手工测试。不要通过修改测试答案或删除测试来“修复”问题。

- 手动输入模式：直接运行程序，不传递参数，输入一行表达式并回车。
- 批量测试模式：传入测试文件路径，文件每行包含一个期望整数和一个表达式，例如：

```text
7 1+2*3
-2 1-3
9 (1+2)*3
```
