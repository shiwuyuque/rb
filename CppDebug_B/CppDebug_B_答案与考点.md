## 3. 逐处详解

### ① `case '+'` 写成减法（易）

**复现**：`1+2` → -1。

**定位**：trace 显示 `eval(0, 2) : 1 + 2 `，分词与根节点都正常 → 直接看 `switch (op_type)` 的 `case '+'`。它和下一行 `case '-'` 长得一样，是最容易拿到的送分点。

**原因与影响范围**：`return val1 - val2;` 把加法当减法。所有含 `+` 的表达式都错，且加法结果常作为其它运算的操作数（例如 `1+2*3` 变成 -5），会继续污染上层；也可能让原本为正的中间结果变负，间接影响除法。

**修复**
```diff
-      case '+'    : return val1 - val2;
+      case '+'    : return val1 + val2;
```

---

### ② `op_level` 初值写成 1（中）

**复现**：`2*3` → `invalid expression`（stderr：「表达式错误：缺少运算符」），`8/2` 同样；但 `1+2` 正常。README 示例里的 `1*2`、`100/1`、`1/100` 一跑就中。

**定位**：
- 「含乘除就非法、含加就正常」这个规律是最大线索；
- 在根节点扫描的 `for` 里打印 `i`、`current_level`、`op_level`，会发现 `current_level = 2` 时 `2 <= op_level` 不成立，一次都没进 `if`；
- 往上看变量声明：`int op_level = 1;`。

**原因与影响范围**：注释里写了「`op_level` 数字越小表示优先级越低」，它作为一个「当前找到的最低优先级」阈值，初值必须**大于所有可能的 `current_level`（1 和 2）**，否则第一个运算符就选不上，循环结束时 `op_type == 0` → 报「缺少运算符」。正确版用 3。改成 1 后，只有 `current_level == 1` 的 `+`（本套里 `-` 被 ④ 提成了 2）能被选中，所以**所有顶层不含 `+` 的表达式全部失效**，403/1000 条。

**修复**
```diff
-    int op_level = 1;
+    int op_level = 3;
```

---

### ③ 根节点选择时不再更新 `op_level`（中难）

**复现**：修好 ② 之后，`2*3+4*5` → 50（期望 26），`1+2*3` → 9（期望 7）。

**定位**：
- `1+2*3` 得到 9，等于 `(1+2)*3` → 说明根节点选了 `*`，优先级没起作用；
- 在扫描循环里打印每次被选中的 `op`，会发现 `2*3+4*5` 最后选的是最右边的 `*`；
- 看 `if (current_level != 0 && current_level <= op_level)` 内部：注释还在讲「`<=` 会保留同级中更靠右的那个」，但 `op_level = current_level;` 这一行不见了。

**原因与影响范围**：`op_level` 必须在每次选中更低优先级的运算符时下降，后面更高优先级的运算符才会因 `current_level > op_level` 被跳过。删掉更新后 `op_level` 恒为初值 3，所有运算符都满足 `<= 3`，**最终 `op` 总是最右边那个顶层运算符** → 表达式变成「从右往左、无视优先级」计算。`2*3+4*5` 被算成 `(2*3+4)*5 = 50`。影响所有含 3 个及以上运算符、且优先级混合的表达式，209/1000 条。

注意：`<=`（同级取最右，保证从左往右）本身是对的，不要顺手把它改成 `<`——那样会变成右结合，引入新的错误。

**修复**
```diff
         if (current_level != 0 && current_level <= op_level) {
           // <= 会保留同级运算中更靠右的那个运算符……
+          op_level = current_level;
           op_type = tokens[i].type;
           op = i;
         }
```

---

### ④ `'-'` 被归到乘除那一档（难）

**复现**：修完前三处后，`1-2*3` → -3（期望 -5）；但 `10-3-2` → 5、`1+2*3` → 7 都正常。

**定位**：
- 失败集中在「减号右边还有乘除」的形状，纯减法、纯加法都正常 → 说明不是 `case '-'` 的运算，而是**优先级分组**；
- 打印每次的 `current_level`：`-` 和 `*` 都是 2，而按注释 `-` 应该和 `+` 同为 1；
- 看 `current_level` 的 if 结构：`'-'` 被塞进了 `* /` 那组。

**原因与影响范围**：`<=` 会在同级里保留**最靠右**的运算符作根。`-` 与 `*` 同为 2 时，`1-2*3` 的根选成最右的 `*`，于是先算 `1-2 = -1`，再 `-1*3 = -3`；正确做法是根选 `-`，先算 `2*3 = 6`，再 `1-6 = -5`。只影响「减法与乘除混排且乘除在右」的表达式，132/1000 条，是四处处最隐蔽的一处。

**修复**
```diff
-        if (tokens[i].type == '+') {
-          current_level = 1;  // + 优先级最低
-        } else if (tokens[i].type == '-' || tokens[i].type == '*' || tokens[i].type == '/') {
-          current_level = 2;  // 其余运算符优先级更高
+        if (tokens[i].type == '+' || tokens[i].type == '-') {
+          current_level = 1;  //+-优先级最低
+        } else if (tokens[i].type == '*' || tokens[i].type == '/') {
+          current_level = 2;  //*/优先级高于+-，低于括号
         }
```

| 题 | 四处埋点主题 |
| --- | --- |
| 上一套 `Debug_2_考题` | 同级结合性 `<=`→`<`、优先级数字对调、括号提前闭合判断被删、负数除法向下取整 |
| `CppDebug_A` | `case '*'` 执行错、`case '-'` 颠倒、根节点扫描漏 `/`、除零判断多加 `val2 < 0` |
